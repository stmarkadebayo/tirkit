| 43 | 2026-11-17 | Judge hardening is in `judge.py` plus a new eval-layer module `injection.py`, on by default (`hardened=True`; `False` is the previous prompt, byte for byte, for measuring and for anyone who needs it). The reply must hold exactly one verdict object with exactly the expected keys (`score`/`winner` and `reason`); prose or `<think>` before it is still accepted, two different verdicts are not. A flag never changes a score. | 45 | 2026-11-17 | PII redaction has three modes (`tirkit.redact.MODES`): `off`, `secrets` (keys and tokens, JWTs, `password=` assignments, Luhn-valid cards, IBANs) and `strict` (also emails, phones, IPv4). Saving `redact_mode` also sets `redact` (`strict` = true) so older readers agree; sending only `redact` maps onto a mode. `Redactor` counts what it replaced; the server adds that count, plus a count the SDK reports in the span attribute `tirkit.redactions`, to `redaction_stats`, shown in Settings. The SDK option `tirkit.init(redact=...)`/`TIRKIT_REDACT` runs in the exporter thread (`_prepare`), not on the caller's thread. The phone pattern now needs a `+`, parentheses or two separators, skips dates and lists of equal-sized digit groups; it changed what `strict` (and old `redact: true` projects) redact slightly: bare digit runs of 7-15 digits are no longer treated as phones, and the existing fixture cases still pass | Keep the boolean and add a second flag; redact in the SDK only | Computing the mode at read time is the safest migration: no data moves and old projects behave as before. The count is one upsert per batch with redactions, off the hot path of the SDK. Server-side redaction runs on the request path: on 100-span batches with a chat payload it added 27% (`secrets`) and 44% (`strict`) to a 7.1 ms request on a non-idle laptop (one cheap pre-check skips the nine key patterns for ordinary text; without it `secrets` was +37%). New projects therefore pay about 2 ms per 100 spans by default; SDK-side redaction moves that cost to the app's exporter thread, and SDK p99 overhead did not change (0.025-0.035 ms with redaction off, `secrets` and `strict`, same non-idle machine).
