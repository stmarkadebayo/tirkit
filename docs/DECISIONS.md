| 29 | 2026-11-17 | `store.py` split into a `store/` package: `base` (connection, transactions, schema), one mixin per domain (`spans`, `datasets`, `experiments`, `scores`, `analytics`, `media`, `config`), `dialect`, `migrations` and `backends`; `SQLStore`, `SQLiteStore`, `PostgresStore`, `open_store`, `Trace` and `MIGRATIONS` are importable from `tirkit.store` as before. `server/app.py` split into `deps` (auth and per-app state), `models`, `openapi` and one router per domain under `server/routers/`; the old `routes_*` extension modules were folded into routers. | 30 | 2026-11-17 | The HTTP API contract is pydantic models in `server/models.py`. Routes declare them as `response_model` but still serialise with `tirkit.serialize.dumps` and return a `Response`, so responses are not re-validated at runtime. Response models forbid unknown fields; request models ignore them (pass-through job payloads allow them). The schema is checked in at `docs/api/openapi.json`; CI regenerates it and fails on a diff. `tests/test_api_contract.py` calls every operation in the schema against a seeded server and validates each JSON response against the schema with `jsonschema`; an operation with no call fails the test | Validate responses at runtime with FastAPI; generate models from the store; test against pydantic models directly | Runtime validation costs time on every request and the hot path must stay cheap. Validating real responses against the published schema in a test catches drift in both directions at no runtime cost. Checking the OpenAPI document (not FastAPI's route objects) keeps the test independent of FastAPI internals, which changed in 0.163 | §3.5, NFR |
| 31 | 2026-11-17 | Request validation errors return 400 with the same `{"detail": "<field>: <message>"}` shape as every other error, not FastAPI's 422 with a list. | 42 | 2026-11-17 | Sampling is head sampling per trace at the root span (hash of the trace id, rules by root name glob or kind, first match wins).
