# Experiment E1: can the LLM judge be trusted?

**Claim tested:** LLM judges are biased by position and length, and calibrating the rubric against
human labels improves agreement (SPEC §9).

E1 has two halves.

## 1. Position bias (no human labels needed)

`research/experiments/e1_judge_bias.py` asks the same model for a one-sentence and a 3-5 sentence answer to
each of the 50 questions in `research/evals/acme_qa.jsonl`, then has the judge compare each pair in both
orders, under the built-in `correctness` rubric (v0) and a calibrated rubric (v1).

```bash
python research/experiments/e1_judge_bias.py --base-url http://localhost:1234/v1 --model qwen/qwen3.5-9b
```

Output: `research/experiments/results/e1_flip_rate.json` (flip rate, first-position win share, long-answer
win share, every pair's verdicts).

## 2. Agreement with humans (needs the maintainer's labels)

Kappa needs real human labels; nobody can fill these in for you.

**Prepared set (the quick route).** `research/labelling/prepare_e1_queue.py` sends the 100 cached
answers of part 1 (a one-sentence and a 3-5 sentence answer to each of the 50 questions, with the
reference answer in the trace input so you and the judge see the same thing) to a Tirkit server,
defines the `correct` score and fills the queue. The labelling rules are in
`research/labelling/GUIDE.md`. With the instance in `~/tirkit-labelling` (start it with
`~/tirkit-labelling/start.sh`, sign in with `LOGIN.txt`), steps 1 to 3 below are already done and you
only label. Do not look at judge scores while you label.

**Part 2 (answers of mixed quality).** In the first batch 94 of the first 99 human labels were 5, because
the model answered with the policy text in front of it. Cohen's kappa says little when almost every
label is the same, so `research/labelling/prepare_e1_part2.py` adds a second queue of 100 outputs: 70
answers the same model wrote *without* the policy text (natural mistakes) and 30 with a defect injected
by rule (a changed fact, an answer to a different question, a vague non-answer, a refusal). Which kind
an item is stays in `items_part2.json` and is not shown while labelling. Report the kinds separately
as well as together: the injected defects are easy for a judge.

1. Send real outputs to Tirkit (the demo app or another app).
2. **Annotation → Score definitions:** create `correct` (numeric 1–5) with this guidance:
   5 fully correct and complete · 4 correct with a minor gap · 3 partly correct · 2 mostly wrong ·
   1 wrong or refused.
3. **Annotation → Queues:** create a queue collecting `correct`, fill it with 100–200 traces, and
   label them yourself (number keys, Enter to submit). Budget: about 1 hour for 100.
4. **Judge reliability:** run a report on that queue with the built-in `correctness` rubric (v0).
   Note kappa, weighted kappa and the length correlations.
5. Calibrate: read the disagreements, edit the rubric (explicit criteria, anchored examples, "ignore
   order and length"), run again. Each edit is a new rubric version with its own row. Stop when
   kappa stops improving.
6. Copy the before/after numbers, with n and the judge model, into the README Results table.

CLI equivalent: export the queue's labels (`Export labels` in the UI), then

```bash
tirkit judge-report labels.jsonl --label correct --rubric correctness --model <judge-model>
tirkit judge-report labels.jsonl --label correct --rubric my_rubric_v1.txt --model <judge-model>
```

## Batch 1 results (provisional, 2026-11-18)

99 of the 100 first-batch outputs were labelled by one person (the maintainer); the judge was
`qwen/qwen3.5-9b` (local, LM Studio) at temperature 0, seeing the same input as the labeller
(question, reference answer, output). Raw data: `results/e1_judge_vs_human/`.

| | Rubric v0 (built-in `correctness`) | Rubric v1 (`research/labelling/rubric_v1.txt`) |
| --- | --- | --- |
| Exact agreement with the human | 53.5% (95% CI 43.8–63.0) | 70.7% (95% CI 61.1–78.8) |
| Mean absolute difference | 0.505 | 0.333 |
| Agreement on one-sentence answers (49) | 80% | 80% |
| Agreement on 3–5 sentence answers (50) | 28% | 62% |
| Judge score vs output length (Spearman) | -0.57 | -0.36 (the human's is +0.10) |
| Cohen's kappa | 0.000 | -0.011 |

**Read this before quoting any of it.**
- The human labels are almost constant: 94 fives, four 4s and one 2. Kappa is close to meaningless
  with labels like that (a judge that always says 5 would agree 95% of the time and still score
  about 0), so it is not a result. Exact agreement is the number that moves, and it is only a
  fair measure here because the judge is not a constant.
- The rubric v1 was written after reading the v0 disagreements **on these same labels**, so
  v0 to v1 is an in-sample improvement. It has not been tested on labels it was not tuned on.
  v1 is frozen; the part 2 labels (answers of mixed quality, see above) are the held-out test.
- What the data says: the judge under-scores longer answers because they add details the
  reference does not mention, which the labelling rules told the human to ignore. Giving the judge
  the labeller's rules removed about half of that. It still docks some long answers ("adds extra
  information").
- What it cannot say: whether the judge catches wrong answers. Only five labels were below 5.
- One labeller, one judge model, answers to 50 questions from one small knowledge base.
